# 平井：D/E（1170-1・1404-4）を、敷地(ABC)本体とは独立に位置・角度調整できるようにする

## 背景（腱さんの発言・2026-08-19）
ABC(1170-4)の形は分割計画図の座標求積表に基づく正確な実測値であることは合意済み。一方、D/E(1170-1・1404-4)は
公図（座標求積表の無い簡易な図面）からの単純トレースで、ABCとの共有境界（西側）は0.1〜0.6mで一致しているが、
それ以外の部分（特に1170-1の東側遠方）はトレース誤差が大きい（1170-1のトレース面積は登記466㎡に対し約303㎡）。

腱さんは「ABCとDEがずれている」と感じており、**DEをABCとは別に、個別に位置調整できる機能が欲しい**とのこと。
現状は`siteAdj`（位置・角度・倍率）をABC・D/E共通の1つの変換(`SITE_XFORM`)で適用しており、動かすと必ず
ABC・D/Eが一体で動く（これは意図通り＝ABCに対するD/Eの相対位置は正確なので、絶対位置を合わせる分には
一体で動いてよい）。しかし**D/Eのトレース自体に誤差があるため、ABCとは別に微調整できる余地が要る**。

## 着手前4問（kaishu-policy）
①同じ知識を持つ場所＝`siteAdj`/`SITE_XFORM`/`toggleAdjust()`一帯（index.html、下記「触る場所」）。
②同種の既存機能＝`siteAdj{lat,lon,rot,scale}`が敷地全体の調整に使っている仕組みと全く同じ考え方
　（位置・角度の差分パラメータ→変換に反映→localStorage保存）を、D/E専用にもう1セット追加すればよい。
③引っ越しか＝No（新規のパラメータ追加。既存のsiteAdjはそのまま、D/E用に別の小さな調整値を足す形）。
④過去の類似改修＝直前のコミット`8becc23`(D/Eの配色統一)・`723ec62`(D/E常時表示化)。
　BUGLOGにD/E関連の記録あり、事前に目を通すこと。

## 設計方針（オーケストレータが決定。実装者は変えないこと）
- 新しい状態 `deAdj = {dE:0, dN:0, rot:0}` を追加する（**倍率は持たせない**。D/Eの面積は既に精度が低く、
  拡大縮小を独立に許すとさらに不確実性が増すため、位置(東西・南北のオフセット、単位メートル)と
  回転(度)だけに限定する）。
- `deAdj`はサイト(hirai)ごとにlocalStorageへ保存する（`siteAdj`と同じ流儀、キー名は`kouteisa_de_adjust_hirai`
  のように既存の`siteKey()`パターンを踏襲した専用キーにする）。物件を切り替えたら該当物件の値を読み直す
  （`siteAdj`同様、`switchSite()`のタイミングで読み込む）。
- **座標変換の適用順序**：D/Eの各点(shape空間のpts、例:`[10.23,72.75]`)に対して、
  1) `deAdj.rot`度だけ、D/E全体の重心を中心に回転
  2) shape空間の東西方向に`deAdj.dE`メートル、南北方向に`deAdj.dN`メートル平行移動
  3) その結果を通常どおり`shapeToLatLngs(pts, SITE_XFORM)`でlat/lonに変換
  （＝ABC用のsiteAdj/SITE_XFORMは一切変更しない。D/Eの点だけ、shape空間に入る前に追加の微調整を挟む）。
- **この変換を通す関数を1つに集約する**：`function deAdjustPts(pts)` のような関数を新設し、
  D/Eの生ptsを渡すと調整済みのpts配列（shape空間のまま）を返す。**既存コードが`SITE.subAreaSets.DE`の
  ptsを直接読んでいる箇所は全てこの関数を経由させる**（後述「触る場所」を全て洗い出して直すこと。
  1箇所でも通し忘れると「地図では動くのに面積計算には反映されない」というズレが起きるので、
  必ず全経路をgrepし直して確認すること）。

## UI（新規追加）
`SITE.subAreaSets && SITE.subAreaSets.DE` を持つ物件でのみ表示する、D/E専用の調整コントロール：
- 見出し「D/E（1170-1・1404-4）を個別に微調整」
- 角度ボタン（既存のABC用ボタンと同じ見た目・同じ刻み：−5°/−1°/+1°/+5°）→ `deAdj.rot`を変更
- 位置調整：ドラッグでもよいし（`drawSubAreaDE()`のポリゴンに`siteAdjustMode`中だけ`interactive:true`＋
  `mousedown`ハンドラを足す、既存の`startSiteDrag`と同様の実装でよい）、東西南北の±ボタン
  （例：±0.5m/±2m刻み）でもよい。**実装者の判断でどちらか、または両方を実装してよい**が、
  最低限「ドラッグ」または「ボタンで数値を動かせる」のどちらか一方は必須。
- 現在値の読み取り表示（例：「東西 +1.5m・南北 -0.8m・角度 +2°」）
- 「D/Eの調整をリセット」ボタン（`deAdj`を`{dE:0,dN:0,rot:0}`に戻す）
- **倍率(拡大縮小)のUIは追加しない**（設計方針のとおり、D/Eには倍率パラメータを持たせない）

## 精度についての注記（必ずUI文言に反映すること）
既存の`#deAccuracyHint`／`deAccuracyHintHTML()`の文言に、今回の機能追加の意味を一言足すとよい。
例：「D/Eは公図からの概算トレースのため、ABCとの共有境界（西側）は高精度で一致していますが、それ以外の
範囲は誤差を含みます。ズレを感じる場合は下の「D/Eを個別に微調整」で位置・角度を補正してください。」
（文言は実装者の裁量でよいが、「共有境界は正確」「それ以外は誤差あり」の2点は必ず含めること）

## 検証（必須・実機）
- D/Eの角度・位置を調整すると、**地図上の描画位置**と**平坦度の区画別内訳の面積**と**価格シミュレーションの
  面積・試算価格**の3つが**すべて同じだけ動く**こと（1箇所だけ動いて他がズレる、という事故が無いこと）。
  具体的には：`deAdj`を変更する前後で、D/E各区画の`trueAreaOfPts`等で計算される面積そのものは
  **変わらない**こと（回転・平行移動は面積を変えないため）。ただし地図上の描画位置・重なり具合は変わること。
- 「配置リセット」（ABC側の既存ボタン）を押してもD/Eの調整値は変わらない（ABC用とD/E用は独立したパラメータ）
  ことを確認。逆に新設の「D/Eの調整をリセット」を押してもABC側(`siteAdj`)は変わらないことも確認。
- 物件を切り替えて平井に戻ってきたとき、保存した`deAdj`が復元されること（localStorage確認）。
- D/Eを持たない他物件（hannan等）でD/E調整UIが出ないこと・エラーが出ないこと。
- コンソールエラーが無いこと。
