# 実装指示書：上の段・D/E区画を非表示にし、「下の段だけ」のアプリにする

対象: `index.html`（**このファイルだけ**。`joukan_20260822.html` は凍結保存版なので絶対に触らないこと）

## 背景・要望（腱さん原文）

> あと大きな方針変更が入った。上の段はがけの影響で使えない。上の段の構想をすべて捨てる、というか
> 非表示というかバックアップ送りにする。機能を戻すことになる。
> （中略）その下の面積一覧表も全部下の段の話だけしてほしい。DとEは一回隠す。DとEは基本なかったことになる。

現地調査の結果、平井物件の**上の段はがけ条例の影響で建築に使えない**ことが判明した。したがって
上の段を前提にした一連の機能（2つの基準面・C+D+E購入シナリオ・上の段の目印点探索）と、
隣接2筆D/Eは、**判断の邪魔になるので画面から消す**。

**退避は完了済み**（着手前に実施）: 上の段・D/Eを含む現行版は `joukan_20260822.html` として
凍結コピー済み・push済み（https://neguracg.github.io/kouteisa/joukan_20260822.html ）。
腱さんが後から上の段の検討結果を見たくなったらそちらを開く運用。

**★重要な制約**: 凍結版は本体と**同じlocalStorageを共有**している（腱さんが調整した敷地配置・公図位置・
上の段の基準点がそのまま見られるようにするため）。したがって本体の改修で
**localStorageのキーを削除・クリアする処理を新たに書いてはならない**（`localStorage.removeItem`/`clear`の
新規追加禁止。既存の`saveXxx()`が値なしでremoveItemする既存動作はそのままでよい）。
上の段のデータは「読まない・書かない・表示しない」だけにして、**消さずに残す**。

## 設計（実装前に決定済み。逸脱する場合は理由をコミットメッセージに残すこと）

### 1. フラグ2本を新設（グローバル定数。将来の復活を1行で可能にする）

`SITES`定義の近く（`let TOOL=...`等のグローバル宣言の並び）に置く:

```js
/* 2026-08-22 方針変更：上の段はがけの影響で使えないため非表示にする（腱さん指示）。
   D/E（隣接2筆）も「基本なかったこと」にする。コードは消さずフラグで殺しているだけなので、
   復活させたい時はこの2行をtrueに戻す。上の段ありの当時の姿は joukan_20260822.html（凍結版）。 */
const SHOW_UPPER_TIER = false;   // 上の段（FLAT_PLANES.high・購入シナリオC+D+E・目印点探索）
const SHOW_DE_REGIONS = false;   // D/E区画（実在の隣接2筆 1170-1・1404-4）
```

### 2. D/Eを消す（チョークポイント1行）

`deSubAreaPolys()`の先頭に追加するだけ:
```js
function deSubAreaPolys(){
  if(!SHOW_DE_REGIONS) return [];   // 2026-08-22：D/Eを非表示（全利用側が空配列を正しく扱う設計）
  const areas=SITE.subAreaSets && SITE.subAreaSets.DE;
  ...
}
```
加えて、**D/E専用のUIパネル**（`deCtrl_D`/`deCtrl_E`/`deAdjBtn_D`/`deAdjBtn_E`/D/E面積表示パネル
`updateDeExtentUI()`が触る要素・`#deAccuracyHint`）を非表示にする。`updateDeExtentUI()`と
`updateSubAreaToggleUI()`の中で、`SHOW_DE_REGIONS`がfalseなら該当DOMを`display:none`にして早期returnする形が素直
（**DOM要素自体は削除しない**＝フラグを戻せば復活する）。

### 3. 上の段を消す（チョークポイント：アクセサ関数を1本挟む）

`SITE.purchaseSets` を直接読んでいる箇所（grep で7箇所。うち2つはHTMLコメント）を、
新しいアクセサ経由に置き換える:

```js
function sitePurchaseSets(){ return SHOW_UPPER_TIER ? SITE.purchaseSets : null; }
```

`updatePlaneSelectUI()`・`updatePlanesUI()`・`runPlaneMaximize()`・`purchaseSetPolys()`・
`exportSitePlannerCSV()`(1572,1604) の `SITE.purchaseSets` を `sitePurchaseSets()` に差し替える。
これだけで「purchaseSetsを持たない物件」＝上の段UIが隠れる既存経路に乗る。

さらに、`FLAT_PLANES.high` が集計・表示に混ざらないようにする:
- `defaultAreaSelectState()`（2856行目付近）: `SHOW_UPPER_TIER`がfalseなら**下の段(low)だけ**を
  既定チェックにする（現在はD/Eを上の段のみ既定チェックにしている＝D/Eが消えるので自然に不要になるが、
  主区画C/Xの`high`も外すこと）。
- `areaSelectCheckboxesHTML()`: 上の段の列/チェックボックスを出さない。
- `tallySelectedAreasByTier('high')` 等の上の段側の集計行・カードを出さない。
- `ACTIVE_PLANE`は常に`'low'`として扱う（`activatePlane('high')`への導線を出さない）。
  **`FLAT_PLANES.high`の値自体は保存されたまま残すこと**（凍結版が読むため。上の制約参照）。

### 4. X区画の目標面積逆算を「下の段の使える面積」基準にする（腱さんの指摘への回答）

腱さん報告:
> XY区画を区画割合でX区画140坪ってやると今X区画の割合16.1%になって、これ何で計算してる？
> 上の段と下の段を合わせてもこれで140坪もある？なんかバグってない？
> やりたいことは、140坪って指定したら下の段が140坪になるところでX区画の仕切りを引いてほしいの

**調査結果（バグではない）**: 押したのは①の「この面積になる%へ反映」(`applyDeTargetArea`)で、
これは**生（そのままの）面積**での割合を計算する（140坪 ÷ 敷地870坪 = 16.09% ≒ 16.1%＝計算は正しい）。
腱さんが欲しいのは②「この使える面積になる%へ反映」(`applyDeTargetUsable`)の方。

ただし②も現状は `bestRefForRegion()` で**X区画内の最適な基準標高を自由に探索**するため、
上の段の平坦面を掴んでしまう可能性があり「下の段が140坪」にはならない。今回の方針変更に合わせ、
**②を「現在の下の段の基準標高で固定して」使える面積を評価する**よう変更する:

- `applyDeTargetUsable()`内の `usableAt(pctE)` を、`bestRefForRegion(...)`（自由探索）から
  **下の段の基準標高で固定した評価**に変える。既存の `usableAreaAtElev(ll, targetElev, thM)`（1509行目）を
  使うこと（新しい計算関数を作らない）。`targetElev` は `FLAT_PLANES.low` の標高、
  それが未設定なら `flatRef.elev` を使い、どちらも無ければ従来どおり「先に平坦度を計算してください」の
  alertで止める。
- **二分探索の前提（単調性）は保たれる**: X区画は%について入れ子に広がる集合であり、
  *固定標高*での使える面積は領域の包含について単調非減少（自由探索版より単調性はむしろ明確）。
  既存のコメントの単調性の説明も、固定標高版の説明に書き換えること。
- ボタンのラベル・`title`属性も「この使える面積(下の段)になる%へ反映」のように、
  ①（生面積）との違いが押す前に分かる文言にする（**同じ文言のボタンが並んで誤操作を招いた前例が
  2026-08-22にあるため**、①②の文言がひと目で区別できることを必ず確認する）。

### 5. 価格シミュレーションの表を整理（DESIGN.md §6 を必ず読んでから）

現在3つある表のうち、②「使える面積比の試算」（チェックボックス連動・`bestRefForRegion`の自由探索）は
上の段が無くなると③「使える面積比の試算（下の段のみ）」と役割が重複し、かつ②は自由探索なので
上の段を掴みうる＝方針に反する。**②を削除し、①（面積比＝生面積）と③（下の段のみ）の2表にする。**
③の計算ロジック・`bestRefForRegion(base.pts, thM)`による基準区画Aの独立計算は**絶対に変えないこと**
（DESIGN.md §6「設計上の注意」に、ここを他の設定に依存させて2回壊した経緯がある）。

## 明示的に「やらない」判断（スコープ外・勝手にやらないこと）

- **コードの物理削除はしない。** 上の段・D/E関連の関数（`activatePlane`/`optimizePlaneForPurchaseSet`/
  `setCdeAnchor`/`deRegionAdj`等）は残す。フラグで到達不能にするだけ。
- **localStorageのデータを消さない**（上の制約）。
- **`joukan_20260822.html` を触らない。**
- **`optimizeFlatRef()`（「使える面積が最大になる基準点を自動で探す」ボタン）の自由探索は変えない。**
  上の段の平坦面を掴む可能性が残るが、これは腱さんが結果を見て使う手動ツールであり、
  勝手に仕様変更せず**報告で言及するに留める**（腱さんの判断待ち）。
- 他物件（函南・古屋・キャンプ場・未公開）の挙動を変えない（元々purchaseSets/DEを持たないので
  フラグ導入の影響を受けないはず＝**実機で無回帰を確認すること**）。

## 受入条件

1. 平井物件の平坦度タブで、上の段関連UI（面の選択トグル・上の段の目印点・目標標高入力・
   C+D+E購入シナリオ）が一切表示されない。
2. 面積一覧表・チェックボックス表・内訳カードが**下の段の数字だけ**を出す（上の段の行・列が無い）。
   カテゴリ別内訳（平ら/軽造成/要造成/超過×坪数）は**必ず維持**（消すと腱さんに叱られた前例あり、
   DESIGN.md §5参照）。
3. 地図・面積集計・がけ2H判定・CSV出力・画像出力のいずれにもD/E区画が現れない。
   D/E調整UIも出ない。
4. X区画で「140坪」を②のボタンで指定すると、**下の段の使える面積が約140坪になる%**で仕切りが引かれる
   （実データで、結果の%における下の段の使える面積を実測して140坪付近であることを数値で確認すること）。
   ①（生面積）のボタンは従来どおり16.1%を返す（こちらは仕様どおりなので変更しない）。
5. 価格シミュが①面積比・③下の段のみ の2表になり、A区画（基準）の値が0や異常値にならない。
6. 他物件（函南・キャンプ場・古屋）に切り替えて、平坦度計算・がけ判定・2H帯生成が従来どおり動く
   （無回帰。特にキャンプ場は両崖モードなので必ず確認）。
7. `SHOW_UPPER_TIER`/`SHOW_DE_REGIONS` を両方 `true` に戻すと、現行（凍結版）と同じ挙動に戻る
   （フラグの往復を実機で1回確認する）。
8. コンソールエラー0件。
