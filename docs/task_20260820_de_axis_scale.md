## 仕様

### 1. deRegionAdjに軸縮尺 `axk` を追加
- `deRegionAdj[region] = {lat, lon, rot, scale, axk}`。既定 `axk: 1`（＝従来と完全に同じ挙動）。
- `loadDeRegionAdj()`で古い保存データ（axk無し）を読んだら `axk=1` を補う（後方互換。読み込み時に落ちない・挙動が変わらないこと）。
- `defaultKouzuAdj()`ではなく`defaultDeRegionAdj()`側の既定値にも `axk:1` を追加。

### 2. 変換の適用順序
`deRegionLatLngs(region)`のshape空間座標→latlng変換において、**回転・一様スケールの前に**軸圧縮を適用する（軸は形状自身の固有方向であり、後から回転しても軸が形状に追随するように）：
```
p_shape → 軸圧縮(axk) → 既存のrot/scale → latlng
```
軸方向はC/D境界（ABC北東辺）の向きで固定：shape空間で正規化ベクトル `u=(0.715, -0.699)`（ABC頂点列の北端(-3.78, 28.6)→東端(27.24, -1.68)の差分を正規化した値。コメントに由来を書くこと）。直交方向 `v=(-u.y, u.x)`。
圧縮アンカーは**形状の重心**（centroid）とする（重心固定なら圧縮でドラッグ位置の感覚が壊れない）：
```
d = p - centroid;  du = (d·u)*axk;  dv = d·v;  p' = centroid + du*u + dv*v
```
centroidはbase pts（DE_D_PTS/DE_E_PTS）から都度計算してよい（変換パイプラインの中で一度だけ）。

### 3. UI：D/E調整パネルに「軸縮尺」ボタン列を追加
`deCtrl_D`/`deCtrl_E`それぞれの角度・倍率ボタン列の下に、同じ見た目で1行追加：
```
軸縮尺  [−5%] [−1%] [+1%] [+5%]
```
- ボタンは `axisScaleDeRegion(region, factor)`（新設）を呼ぶ。`deRegionAdj[region].axk *= factor`、下限0.3/上限2.0でクランプ、保存(`saveDeRegionAdj`)、再描画（既存の`rotateDeRegion()`と同じ後処理経路を流用）。
- `updateDeExtentUI()`の面積表示行に軸縮尺も出す（例:「…（倍率1.07・角度0°・軸0.85）」。axk=1のときは「軸1.00」でも省略でもよい、既存フォーマットを崩さない範囲で）。
- 説明文（hint）に1行:「軸縮尺＝C/D境界の方向（北西→南東）に沿ってだけ伸縮します。公図と比べて一方向だけ長すぎる/短すぎる時に使ってください」。

### 4. 面積指定との相互作用
軸圧縮で面積はaxk倍に変わる。既存の`setDeRegionArea()`は「現在の実面積を測って目標面積になるよう一様スケールを補正する」実装のはず（要確認）なので、axk適用後の実面積を測っていれば自動的に整合する。**実機で「軸縮尺を変える→面積で指定466を再入力→面積が466になり軸比率は保たれる」ことを確認すること。** もし`setDeRegionArea()`が実面積ではなく理論値から逆算していて食い違う場合は、実面積ベースに直す（同じ知識を2箇所に持たない）。

### 5. リセットとの整合
`resetDeRegion(region)`がaxkも既定値1へ戻すことを確認（defaultDeRegionAdj()を使っていれば自動で満たされるはず）。

3. 公図オーバーレイ（kouzuToggle）をONにして、軸縮尺0.8前後でDの半島・出っ張りが公図ピンクの帯に近づくことを確認。

5. 「面積で指定」466を入力→実面積が466になること、axkが保存されたままであることを確認。
6. リセットボタンでaxk=1に戻ることを確認。
7. E区画側でも同じボタンが動くことを確認（既定1のまま触らなければ従来と同一挙動）。
8. D/Eを持たない他物件（函南等）に影響が無いこと（deExtentWrap自体が非表示）を確認。
