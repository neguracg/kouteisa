# 平井：D/Eを常時表示化＋切替はABC⇄XYの2択へ＋パネル上下入替＋D/E描画色の修正

## 背景（腱さんの指摘・2026-08-18）
前回の実装で区画割案を ABC→XY→DE の3案循環にしたが、**設計の意図が違っていた**。正しくは：

- **D区画(1170-1)・E区画(1404-4)は「常に」地図に描画される**。これらは実在の隣接筆であり、
  ABC/XYという「同じ敷地(1170-4)をどう割るかの案」とは次元が違う。案の切り替え対象にしてはいけない。
- **切り替えスイッチは ABC ⇄ XY の2択に戻す**（従来どおり）。DEはこの循環から外す。
- **表にもDEが常に出る**（平坦度の区画別内訳・価格シミュレーションの両方）。下にスクロールすれば
  DEの分が見える、という状態にする。
- **地図上のD/E区画が白い破線で描かれていて、下地（航空写真・標準地図とも明るい）に埋もれて見えない。**
  はっきり見える色にする。
- **パネルの上下を入れ替える**：現在「価格シミュレーション」が上・「高低差ごとの面積一覧(#flatResult)」が下。
  これを逆にして、**上＝高低差ごとの面積一覧、下＝価格シミュレーション** にする。

## やること

### 1. 切替はABC⇄XYの2択に戻し、DEを常設化
- `toggleSubAreaVariant()`が`Object.keys(SITE.subAreaSets)`で全キーを循環している現状を、
  **`ABC`と`XY`だけを循環対象**にする（`DE`をスキップ）。実装方法は実装者判断でよいが、
  「循環対象キーの配列」を1箇所に切り出して両方（トグルと表示ラベル）がそれを見る形が望ましい
  （知識の二重管理を作らない）。
- `subAreaVariant`が`'DE'`になることは無くなる。`updateSubAreaToggleUI()`のボタン文言
  （「区画割案 / ABC / （クリックでXY案に切替）」）も2択前提に直す。
- `#deSplitPanel`（%スライダー）の表示条件は従来どおり`subAreaVariant==='XY'`のときだけ有効
  （ABC選択中はグレーアウト。この挙動は既存のまま維持する）。

### 2. D/Eを常に地図に描画
- `subAreaPolys()`は「現在選択中の案の区画」を返す関数。これは**ABC/XYの切替表示にのみ使う**まま残す。
- **新たにD/E（`SITE.subAreaSets.DE`）を常時描画する経路を追加**する。`drawFlat()`内で
  `subAreaPolys()`を描いている箇所（1887行付近）の直後に、DEも同様に描く。
  ※ ただし平坦度グリッド未取得(`FLAT_GRID`なし)でもD/Eは見えてほしいので、`drawFlat()`だけに
  依存させず、**敷地描画(`redrawSitePolygon()`または`drawSite()`)の経路でも描かれる**ようにすること。
  レイヤーは`flatLayer`ではなく専用のレイヤー（例：`subAreaLayer`を新設し常に`map`に追加）にするのが
  望ましい（`flatLayer`は平坦度タブ以外では地図から外れるため）。**どちらの経路でも二重に描かれない**
  ように、レイヤーを`clearLayers()`してから描くこと。
- **色**：白(`#ffffff`)をやめ、下地が明るくてもはっきり見える色にする。
  - ABC/XYの区画境界（既存の白破線）→ 濃い色に変更（例：`#1a2b3c`系の濃紺、または`#7c3aed`系）。
    ※既存の`#0d7a37`（50cm境界の緑太線）・`#ff2d2d`（基準ライン赤）と紛れない色を選ぶこと。
  - D/E（実在の隣接筆）→ ABC/XYとは**別の色**にして、種別が違うことが一目で分かるようにする
    （例：オレンジ系`#e0a458`。`#deAccuracyHint`の文字色と揃えると意味的に一貫する）。
  - 実線/破線の使い分けでも区別をつけてよい（D/E＝実在の筆なので実線、ABC/XY＝計画上の分割なので破線、等）。
  - ラベル（区画名）も地図上に出ているので、同じ色・視認できる背景（既存の`rgba(15,23,32,.75)`背景の
    divIconと同じ作法）で描くこと。

### 3. 表にもD/Eを常に出す
- **平坦度の区画別内訳**（`computeFlatAreasCutFill()` / `computeFlatAreasLegacy()`）：
  現在は`subAreaPolys()`（＝選択中の案）だけをループしている。これを
  「選択中の案（ABCまたはXY）→ その後に必ずD/E」の順で出すように変更する。
  見出しは「区画別の内訳（ABC）」の後に「隣接筆（D/E）」のような別見出しを立てて、
  **同じ敷地の分割案なのか、別の実在筆なのかが混ざらない**ようにすること。
  D/Eの見出し直下には既存の`deAccuracyHintHTML()`（概算トレースの注意書き）を必ず付ける。
- **価格シミュレーション**（`priceSimGroups()`）：同様に「選択中の案＋常にDE」を返すようにする。
  現状の`if(subAreaVariant==='DE')`のような分岐は不要になる。
  **注意**：ABC小計（またはXY小計）は敷地全体と一致するが、**DE小計は別の土地なので一致しない**。
  これは正しい挙動なので、DE小計の行に「（別地・敷地面積には含まれない）」等を明記して、
  誤りに見えないようにすること（既存コメントに同趣旨の記述があるので踏襲）。

### 4. パネルの上下入替
- 平坦度カード内で、`#flatResult`（高低差ごとの面積一覧）が`#priceSimPanel`（価格シミュレーション）
  **より上**に来るようにHTMLの並びを変更する。
- 単純にHTML要素の順序を入れ替えるだけでよい（両者とも中身はJSが`innerHTML`で描くので、
  JS側の変更は不要なはず）。ただし`#priceSimPanel`の表示/非表示制御が
  `updateSubAreaToggleUI()`にある点に注意し、入替後も正しく機能することを確認すること。

## 検証（必須・実機）
- 区画割案ボタンを繰り返し押し、**ABC⇄XYの2択でのみ循環し、DEには切り替わらない**こと。
- **ABC選択中でもXY選択中でも、地図上に常にD区画(1170-1)・E区画(1404-4)が描かれている**こと。
- 平坦度計算をしていない状態（`FLAT_GRID`なし）でもD/Eが地図に描かれること。
- D/Eの線色が航空写真・標準地図の両方ではっきり見えること（`photo`レイヤーに切り替えて確認）。
  ABC/XYの区画線とD/Eの線が色で区別できること。
- 平坦度の結果表に「選択中の案の区画別内訳」＋「隣接筆D/E」が両方出ること。D/Eには精度注意書きが付くこと。
- 価格シミュレーションの表にもD/Eが出て、DE小計が別地である旨が分かること。
- 平坦度カード内で高低差ごとの面積一覧が価格シミュレーションより**上**に表示されること。
- ABC選択中の従来動作（面積999.9/1000.0/876.6㎡）に回帰がないこと。
- 他物件（hannan等、subAreaSetsを持たない）でエラーが出ないこと・区画UIが非表示のままであること。
- コンソールエラーが無いこと。
